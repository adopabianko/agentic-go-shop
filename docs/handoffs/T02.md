## Behavior delivered

`(*memory.Store).ApplyAdjustment` implements `contracts.AdjustmentRepository` using the store's existing `WithinTx` serialization and copy-on-write state. It fingerprints SKU, quantity, and the exact reason; stores successful receipts in the predeclared adjustment ledger, separate from order request keys; and updates available stock atomically with the receipt. Same-key/same-payload calls return the original UTC receipt, while a changed payload conflicts. Unknown SKU, total quantity above `domain.MaxQuantity`, random ID failure, transaction errors, and cancellation before commit do not commit stock or consume the key.

The tests exercise the real memory adapter and order service. They cover replay, key namespace separation, stock bounds and failed-key retries, concurrent same-key requests, concurrent order create/cancel alongside an adjustment, and cancellation immediately before commit.
